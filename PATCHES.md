# Changes to the upstream sources

Each change is a patch in `patches/`, applied by `update-rs-matter.sh` after the crates are laid
out. All are to rs-matter's own crates; the third-party crates are as published.

| Patch | File | What | Why |
|---|---|---|---|
| `0001-dm-clusters-pregenerated` | `rs-matter/rs-matter-dm-clusters/src/lib.rs` | `include!("generated/clusters_generated.rs")` instead of `include!(concat!(env!("OUT_DIR"), "/clusters_generated.rs"))` | Soong does not run build scripts. The code `rs_matter_codegen::generate` writes in `build.rs` is generated by `update-rs-matter.sh` into `src/generated/`, only the clusters in `clusters.txt` |
| `0002-utils-build-time` | `rs-matter/rs-matter-utils/src/epoch.rs` | `include!("build_time.rs")` instead of the file `build.rs` writes into `OUT_DIR` | the same; `src/build_time.rs` (`FIRMWARE_BUILD_MATTER_US`, the lower bound of the Last Known Good UTC Time) holds the time of the update instead of the time of the build |
| `0003-crypto-boringssl-aead` | `rs-matter/rs-matter-crypto/src/backend/openssl.rs` | AES-CCM through BoringSSL's AEAD (`EVP_aead_aes_128_ccm_matter`, `EVP_AEAD_CTX_seal`/`open`) instead of the EVP_CIPHER `Cipher::aes_128_ccm()` | Android's openssl crate is BoringSSL's: it has no AES-CCM cipher (`#[cfg(not(boringssl))]`), BoringSSL has CCM only as an AEAD, with Matter's parameters (16-byte tag, L=2, 13-byte nonce). The four functions are declared in the file: `bssl_sys`, the crate with BoringSSL's bindings, is visible only to a few AOSP modules |

Without a build script, the cfgs some crates' `build.rs` would set are in `tools/gen_bp.py`
(`CFGS`, for rustc 1.95): `pinned-init` and `pinned-init-macro`. The other build scripts set
nothing for aarch64 Android and x86-64 Linux (`async-io`, `defmt`, `defmt-macros`,
`embassy-sync`, `embassy-time-driver`, `embassy-time-queue-utils`, `embedded-hal-async`).
